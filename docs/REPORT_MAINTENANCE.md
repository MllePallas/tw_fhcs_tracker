# 分析報告維護

網站報告從 2026/06 起提供。目前公開 2026/06、2026/07、2026/08；未來月份隨資料更新自動新增。

## 修改報告

在 GitHub 編輯 `docs/reports/YYYY-MM.md` 並提交即可。GitHub Actions 會重新產生相同月份的 HTML，保留你修改的文字。不要直接改 HTML，下一輪會由 Markdown 重新排版。

2026/06、2026/07 由新版流程生成後完成內容核對與修訂；2026/08 是已確認的人工修訂版。後續排程保留內容；若輸入資料更新，會提示資料已有變動，不自動覆蓋文字。

需要整份重新生成時，開啟 Actions → Generate Monthly Analysis → Run workflow，指定西元月份並勾選 overwrite_manual。未勾選時保留人工修訂。

## 自動流程

1. 更新月自結、市場與新聞資料。新聞以媒體為主，已取得的摘要在公告月8～20日最多每24小時補抓一次；人工摘要保留。補抓失敗不清空舊內容。
2. 建立同一份分析資料包，計算MoM、YoY、近三月、子公司殘差與排除主要公司後的群體變化。
3. 讀取已收集來源的原始文章；過早發布或明確異期的來源不納入原因分析。無法讀取原文時，既有合格摘要只能以二次來源身分引用。不等待官網。
4. 產生分析文字。文字中的數字只能引用程式計算代碼，新聞原因須附有效來源；另作一次語意校對，檢查公司／期間、趨勢、排名與原因對應。未通過則有限次數修正。
5. 產出Markdown、HTML、來源稽核與索引並自動發布，不設人工審查關卡。首次生成失敗時明示分析未完成；後續刷新失敗時保留既有完整報告。

數字檢查與模型校對可降低錯誤，不能保證新聞解讀完全無誤；仍可直接修改Markdown。新聞全文不存入公開報告，只保存引用連結、來源類型與內容雜湊。

## 檔案

- `YYYY-MM.md`：可直接修改的正式內容。
- `YYYY-MM.html`：網站頁面，由程式產生。
- `YYYY-MM.pack.json`：分析資料包。
- `YYYY-MM.analysis.json`：自動生成的原始草稿及數字代碼；人工修訂後以Markdown正式內容為準。
- `YYYY-MM.evidence.json`：原始來源及核對資訊，不含新聞全文。
- `YYYY-MM.meta.json`：產稿狀態、人工修改及資料更新狀態。

早於2026/06的舊版報告封存於網站目錄外的 `archive/reports`。歷史獲利資料、趨勢比較及Excel下載不受影響。
